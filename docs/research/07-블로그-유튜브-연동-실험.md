# 07. 블로그·유튜브·홈페이지 연동 실험 (GitHub Actions에서 실제 확인)

## 요약 (5줄)

1. 이 작업 환경에서는 네이버·유튜브에 접속할 수 없어서, 임시 브랜치 `probe-blog` 의 GitHub Actions 작업으로 실제 응답을 확인했다(2026-10-16, 도구는 `tools/probe/`).
2. 블로그 RSS는 200(글 50개), 글 본문 페이지도 200이고 본문·사진 설명·소제목을 읽을 수 있다. 사진은 주소 끝에 `?type=w800` 을 붙이면 받을 수 있다(그냥은 404).
3. 유튜브 설명란 화면에는 블로그 주소가 `blog.naver.com/gayayangpyeong...` 로 잘려 보이지만, 내부 `next` 응답의 링크(`redirect?q=`)에는 **글 주소 전체**가 들어 있다 → 영상 ↔ 블로그 글을 정확히 짝지을 수 있다.
4. 그래서 `scripts/update_videos.py` 가 이제 설명란 링크의 원래 주소를 `videos.json` 의 `links` 에 저장한다(커밋 487ab7b). 2026-10-16 04:42 기준 68개 중 66개에 `links` 가 있고, 매물 영상 3개(d9zp8vq_SFk·Yp4KhcA1YDw·T1bnKBqf4J4)가 글 주소까지 연결됐다.
5. 유튜브 썸네일·자동 장면 이미지(maxresdefault 1280×720, hq1~3)도 받을 수 있다. 블로그에 글을 쓰는 API는 없고 유튜브 설명란 수정은 사장님 계정 인증이 필요하므로, 반대 방향 링크는 사장님이 붙여 넣는 문구로 한다.

## 실험 방법
- `probe-blog` 브랜치(독립 이력)에 `probe.py`·`snapshot.py` 와 그 브랜치에서만 도는 작업 파일을 올림 → Actions가 실행 →
  결과를 `::notice::` 주석(probe)과 브랜치 커밋(snapshot, 커밋 aa7ff87)으로 남김 → 공개 GitHub API(check-runs/annotations)와 `git fetch` 로 읽음.
- 받은 원본은 줄여서 `tests/fixtures/raw/` 에 있음. 자세한 방법은 `tools/probe/README.md`.
- **`probe-blog` 브랜치는 아직 GitHub에 남아 있음** — 이 환경에서는 브랜치 삭제가 막혀 있어 사장님이 지워야 함:
  https://github.com/phg908-dot/gaya-homepage/branches

## 확인한 사실

### 네이버 블로그
- RSS `https://rss.blog.naver.com/gayayangpyeong.xml` → **200**, 103,987바이트, **글 50개**.
  항목마다 제목, 링크(`https://blog.naver.com/gayayangpyeong/<logNo>?fromRss=true…`), 날짜, 요약(약 600바이트), 썸네일 1장(`blogthumb.pstatic.net …?type=s3`).
- 매물 글 제목 예: "양평 전원주택 매매｜전기요금 월 5천 원 정남향 집, 용문 금곡리 768평"(2026-10-13),
  "지평면 토지 매매 가격 인하, 지평역 450m 전용비 없는 대지 200평"(2026-10-01),
  "양평 토지 매매｜지평면 개울 옆 전원주택지, 561평 값에 1,126평 2억 3천"(2026-10-01).
  나머지는 지역 이야기·칼럼("지평막걸리 직판장과 옛 지평양조장", "양평 매립장 2057년까지 연장", "양평 농촌체류형 쉼터, 땅 계약 전에 확인할 5가지" 등).
- 글 페이지 `https://m.blog.naver.com/PostView.naver?blogId=gayayangpyeong&logNo=<logNo>` → **200**(약 125KB).
  본문은 `class="se-main-container"` 안에 있고 사진 설명("위에서 내려다본 집과 마당, 비닐하우스, 가꾼 밭, 태양광 모습입니다.")과
  번호 붙은 소제목("1. 태양광 2기, 전기를 써도 한 달 약 5천 원", "2. 정남향 주택, …")이 들어 있다.
- 사진: 글 하나에 약 20장, `https://mblogthumb-phinf.pstatic.net/...`. **주소 그대로는 404**, `?type=w800` → 200 JPEG 약 160KB,
  `?type=w966` → 약 230KB. 서버에서 받을 때 Referer는 필요 없었다. 브라우저에서 우리 도메인으로 직접 띄우는 것(핫링크)은 **시험하지 않음** → 저장소로 내려받아 쓰는 방향으로 계획.
- 블로그 본문은 사무소를 "지평역 앞 지평부동산, 양평 가야부동산(가야공인중개사) 박홍균"으로 소개한다
  (홈페이지에서는 별칭을 쓰더라도 등록 상호 '가야공인중개사사무소'와 함께 써야 함).

### 유튜브
- 내부 요청 `POST https://www.youtube.com/youtubei/v1/next`(이미 `update_videos.py` `fetch_next_details()` 가 사용)의
  설명란 링크에 **글 주소 전체**가 `redirect` 주소의 `q=` 값으로 들어 있다.
  예: d9zp8vq_SFk → `q=https%3A%2F%2Fblog.naver.com%2Fgayayangpyeong%2F224427678503`.
  설명란 글자(`attributedDescription.content`)에는 `https://blog.naver.com/gayayangpyeong...` 처럼 잘린 주소만 있다.
- 썸네일 `https://i.ytimg.com/vi/<id>/…`: `maxresdefault.jpg`(1280×720) 200 · 406,633바이트, `sddefault` 200, `hqdefault` 200,
  `hq1`·`hq2`·`hq3`(480×360 자동 장면) 200, `1`·`2`·`3.jpg`(작은 장면) 200.

## 저장소에 반영된 것
- `scripts/update_videos.py` (커밋 487ab7b, 2c33ea3):
  - `description_links()` — `attributedDescription.commandRuns` 의 링크에서 `redirect?q=` 를 풀어 원래 주소를 얻고, 설명란 글자 속 주소와 합쳐
    최대 10개(`LINK_MAX`)를 `links` 에 저장. 유튜브·구글 주소는 뺌. 화면용으로 잘린 주소(`...`, `…`)는 버림.
  - 설명란 다시 읽기: 링크를 아직 모르는 영상은 한 번에 30개까지, 본편은 매시간 6개씩 돌아가며 → 사장님이 유튜브 설명란에서 가격 등을 고치면 홈페이지 자료에도 반영.
    주소 표기만 다른 경우(`_same_text()`)는 바뀐 것으로 보지 않아 쓸데없는 커밋을 막음.
  - 설명란은 5,000자(유튜브 최대)까지 보존(`DESC_MAX`). 조사 당시에는 2,000자에서 잘려 설명란 끝의 사무소 정보가 사라질 수 있었음.
- 테스트 자료: `tests/fixtures/raw/` (블로그 RSS·글 HTML, 줄인 `next` 응답). 이 자료를 `fetch_next_details()` 에 넣으면 위 표와 같은 링크가 나오는 것을 확인함.

## 아직 안 한 것 (기획 대상 — `docs/plan/`)
- 블로그 RSS·글 본문·사진을 매시간 작업에서 수집(`data/blog.json`, 사진은 `public/images/blog/<logNo>/NN.jpg` 로 줄여 저장, 개수·용량 상한, 글 삭제·거래완료 시 정리).
- 매물(영상)별 상세 페이지에 블로그 사진·소제목·사진 설명을 싣고 "블로그 글 전체 보기"·"유튜브에서 보기" 링크.
- 홈페이지 → 유튜브/블로그 방향: `admin/youtube.html` 이 만들어 주는 설명란 끝 한 줄(홈페이지 매물 주소), 채널·블로그 프로필 링크(사장님 1회).
- 거래완료 처리 한 곳으로: 유튜브 제목 또는 블로그 제목에 '거래완료/매매완료'가 붙으면 한 시간 안에 홈페이지에서 빠지게.
- 블로그 본문·사진 설명에 지번이 있으면 지우기, 일치건축 연락처 묶음은 사무소 정보로 쓰지 않기.
