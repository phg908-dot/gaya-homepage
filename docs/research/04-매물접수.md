# 04. 휴대폰 매물 접수와 '유튜브 보고 내 매물 내놓기'

## 요약 (5줄)

1. 조사 당시 `sell.html` 은 입력이 많고(실측: 글자 77자 + 선택 2개), PC에서는 '내용 복사' 후 직접 카톡·문자로 보내는 방식이라 휴대폰·고령 손님에게 불편했다.
2. 조사의 1순위 추천은 서버 없는 탭 위주 양식 + 문자 앱 자동 작성(`sms:`) + 전화 버튼, PC는 QR이었다.
3. **그 뒤 사장님 결정**: '보내기'를 누르면 사장님 휴대폰으로 문자가 바로 오게(문자 중계 — "추천대로 해줘"), **QR·복사는 쓰지 않음**("나이 든 사람들은 번거롭게 생각해"). → 시제품 `tools/relay/`. 이 문서의 QR·복사 추천은 더 이상 유효하지 않다.
4. 모든 유튜브 영상(매물·법령·쇼츠)에서 '내 땅·집 내놓기'로 오게: 설명란 기본값 1줄, 채널 링크, 고정 댓글, `sell.html?v=영상ID`(어느 영상을 보고 왔는지 문자에 자동 기재).
5. 개인정보: 문자 앱 방식은 저장 없음, 중계·양식 방식은 수집·이용 안내와 처리방침 필요. 법령 영상의 문구는 '상담·접수 창구'로 중립적으로(고가 매도 보장 등 금지).

> 아래는 2026-10-16 조사 결과 원문입니다. 임시 폴더 경로를 지우고, 다른 사무소·가게의 연락처와 개인 이름, 지번을 가린 것 외에는 그대로 두었습니다.

## 원본 조사 결과 (요약 보고)

I've audited the current sell page on emulated phones, researched the alternatives, and written up a ranked plan. The best phone flow needs no server and no setup from the owner: a tap-only form that opens his phone's text app with the message already written. Nothing under `/home/user/gaya-homepage` was changed.

### What's wrong with the current sell.html (tested on iPhone, Android and desktop sizes)
- **Too much typing.** A realistic entry took 77 typed characters plus 2 dropdowns. The "문자로 보내기" button sits 1,322px down on an iPhone, about 1.6 screens. Phone number is required even though a text message already shows the sender's number.
- **Dropdown defaults are always sent.** If the seller never touches them, the message still says "종류: 토지 / 거래: 매매". The owner can't tell a real choice from a default. A blank name is sent as "성함: -".
- **The text link is the same on iPhone and Android:** `sms:01034060071?&body=<encoded>`. The sample message was 139 characters (216 bytes), so it goes as a long text (LMS). It reads well, line by line. But it doesn't say which video or page the seller came from, or when they can take a call.
- **No way to send photos.** On phones, the bottom bar only shows [☎ 전화], so there's no "내놓기" button anywhere. Copying the message works.
- **Desktop users have nowhere to send it.** "내용 복사" works, but there's no Kakao channel and no published email. The side "문자 문의" button is still a text-message link on PC, which does nothing on Windows.
- **What the owner receives:** a long text at 010-3406-0071 (`office.mobile` is empty, so it falls back to `office.tel`), or a picture message if the seller adds photos.
- **Not yet checked on real phones.** The emulation confirms the link that gets built, not that the iPhone and Samsung text apps fill in the message.

### Ranked recommendation
1. **Now, no server, no owner setup:** replace the dropdowns with tap buttons.
   - Choices: type, deal, the 12 양평 읍·면 plus "양평 외", optional 리, low-pressure options ("아직 고민 중", "시세만 궁금", "세금 먼저 상담", "농지 전수조사 관련", "상속받은 땅"), and best time to call.
   - Phone number becomes optional, and anything not chosen is left out of the message.
   - A fixed bottom bar shows [문자로 보내기][전화], plus one line: "문자 앱에서 ＋로 사진 3~5장".
   - Opened as `sell.html?v=<videoID>`, the page shows the video title and adds "본 영상: …" to the text, so the owner sees which video brought the seller.
   - On PC, show a QR code to continue on the phone, plus copy and phone.
   - I built a mock-up outside the repo: 7 taps and 3 typed characters produced a 108-character message.
2. **Automatic, on the site:**
   - Add a "내 땅·집 내놓기" button (`?v=ID`) on every video card and listing page.
   - Make the phone bottom bar [전화][내놓기].
   - Add a section for the 농지·세금·법령 videos. All 42 of them are missing from the site today; 14 are full-length.
3. **YouTube, one-time, about 5 minutes for the owner:**
   - Put one line with the link in **YouTube Studio's default upload description**, so every new upload carries it.
   - Add one "땅·집 내놓기" link to the channel's header links.
   - Shorts links haven't been clickable since 2023-08-31, so Shorts should use the "related video" link to point to a full video.
   - Pinned comments work on full-length videos.
   - On the 법령 videos, the button must stay a neutral "상담·접수 창구". The owner's descriptions already say "매도·위탁을 권하지 않습니다", so no fear-based or "sell now" wording.
4. **Upgrade A, Kakao channel:** the owner creates a free channel, turns on 1:1 chat and puts `pf.kakao.com/_xxxx/chat` into `site.json` `office.kakaoChannel`. The existing `fillOfficeBits` code already accepts that link. The flow becomes "copy, open the chat, paste", and Kakao sends full-quality photos. I found no documented way to pre-fill the chat message.
5. **Upgrade B, one-time Google setup:** a Google Apps Script web app that saves to a Sheet, puts photos in Drive and emails the owner. Submission and photos then happen inside the page, at no cost. The site would then be storing personal data, so it needs a privacy page, a retention period, notice of overseas storage, and spam guards.
6. **Not recommended:**
   - Formspree and Web3Forms: photo upload is paid only.
   - Google Forms: uploading a file requires the seller to sign in to Google.
   - Web Share API as the main route: the seller has to pick the recipient themselves, and it doesn't work inside the KakaoTalk or Naver app browsers on Android.

### Legal (general information, not legal advice)
- **Text-message approach:** the site stores nothing, so no consent box is needed. The office may reply using what the seller sent without separate consent, under 개인정보보호법 제15조①4 (2023 amendment). Using it for marketing needs consent, and leads that go nowhere should be deleted after a set period.
- **Form backend (Upgrade B):** adds duties under 제30조, 제26조 and 제28조의8. Never ask for 주민번호 or ID photos.
- **공인중개사법:** taking listings is normal business; the required office details are already in the site footer. Avoid "고가 매도 보장" and unsupported price claims or fee promises (제33조). If fees are mentioned, say "법정 한도 내 협의".

### Not verified
- 발품탑 (top4949.com was blocked with a 403 and returned no search results) and 전원닷컴 intake forms.
- Details of Naver's, 직방's and 다방's owner-listing screens. Web pages wouldn't open here, so the platform research rests on search results only.
- Whether the channel is in the YouTube Partner Program, which decides if end screens can link to the website.

The 031-772-2060 and [일치건축 이메일] in video descriptions belong to the 일치건축 block. Don't use them as intake contacts without the owner confirming.

#### 1. 현재 sell.html 휴대폰 감사 (Playwright 실측)

환경: `python3 -m http.server 8765 --bind 127.0.0.1` (root = /home/user/gaya-homepage/public), Chromium 1194
(`/opt/pw-browsers/chromium`), iPhone 390×844 isMobile·hasTouch·iOS 18.5 UA / Android 412×915 Galaxy UA / 데스크톱 1280.
sms: 이동은 CDP `Page.frameRequestedNavigation` 으로 실제 생성 URL을 잡음.
스크린샷: `sell/{iphone,android,desktop}-0N-*.png` (01 첫화면, 02 전체, 03 빈 값 제출, 04·05 입력, 06·07 제출 후, 08 복사, 09 옆 패널).

##### 1-1. 화면 구조
- 첫 화면(iPhone)에는 제목·설명·성함·연락처·소재지까지만 보이고, **"문자로 보내기" 버튼은 페이지 위에서 1,322px(iPhone)/1,300px(Android)** — 화면 1.6장 아래. 문서 전체 높이 2,305px.
- 입력 8개: 성함(text) · 연락처*(tel, inputmode=tel, autocomplete=tel) · 소재지*(text, autocomplete 없음) · 매물종류(select 9개) · 거래(select 4개) · 면적(text) · 희망가격(text, 숫자 키패드 아님) · 추가내용(textarea).
- 글자 크기 16px → iOS 확대(줌) 문제 없음. 칸 높이 44~48px로 터치 크기는 충분. 사진(input file) 없음. 동의 문구 없음(저장 안 하므로 정상).
- 휴대폰 하단 고정바(mbar): **[☎ 전화] 1개만** 보임. '카톡' 버튼은 카카오 채널이 없어 숨김 → 휴대폰 어디에서도 "내놓기" 상시 버튼이 없음.
- 옆 패널 "카카오톡으로 상담" 버튼은 채널이 없어 **"문자 문의"(sms:)** 로 바뀌어 보임(정상 동작).

##### 1-2. 입력량 (현실적인 예시: 김영희 / 010-1234-5678 / 양평군 지평면 월산리 / 밭 600평 / 2억 / 메모)
- **직접 타이핑 77자 + select 2번**. 최소(필수만)도 전화번호 11~13자 + 소재지 수 글자.
- 연락처가 필수인데, 문자로 보내면 **보낸 사람 번호가 이미 찍히므로 중복 입력**.
- select 는 기본값이 '토지'/'매매' → 손대지 않아도 문자에 "종류: 토지 / 거래: 매매"로 나감 → **사장님은 고른 건지 기본값인지 구분 불가**.
- 성함을 비우면 "성함: -" 줄이 그대로 나감(잡음).
- 소재지 칸이 자유 입력이라 고령 매도인이 "양평 지평 월산리 밭" 같은 형식으로 섞어 씀 — 읍·면을 탭으로 고르게 하면 해결.

##### 1-3. "문자로 보내기"가 만드는 것 (실측)
- iPhone·Android **동일**(코드가 OS 분기 안 함): `sms:01034060071?&body=<URL 인코딩 본문>`
- 예시 본문 (139자, 한글 2바이트 기준 216바이트 → 90바이트 초과라 **장문(LMS)** 로 발송됨, 대부분 요금제 무료):
  ```
  [홈페이지 매물 접수]
  성함: 김영희
  연락처: 010-1234-5678
  소재지: 양평군 지평면 월산리
  종류: 토지 / 거래: 매매
  면적: 밭 600평
  희망가격: 2억
  내용: 포장도로 접함, 농지 전수조사 문자 받고 문의드립니다. 평일 오후 통화 가능
  ```
  URL 전체 길이 865자. 읽기 좋음(항목별 줄바꿈). 부족한 것: **어느 영상/페이지를 보고 왔는지 없음**, 통화 가능 시간 칸 없음, 사진 안내 없음.
- `?&body=` 는 iOS·안드로이드 양쪽에서 된다는 **커뮤니티 보고**가 다수(공식 규격 아님). 정석은 RFC 5724 `sms:번호?body=`(안드로이드), iOS 8+ 는 `sms:번호&body=`.
  → 실제 기기(아이폰 + 갤럭시 삼성메시지/구글메시지)에서 1회 확인 권장. 헤드리스 에뮬레이션은 "어떤 URL을 만드는가"까지만 확인 가능, 메시지 앱이 본문을 채우는지는 실기기에서만 확인 가능.
- 수신자: site.json 의 `office.mobile` 이 비어 있어 `office.tel`(010-3406-0071)로 감. 사장님 휴대폰이면 OK.
- 문자 앱에서 돌아온 뒤 화면에 미리보기만 남고 "보내셨나요?" 안내가 없음(중복 발송 가능, 큰 문제 아님).
- "내용 복사"(휴대폰): 클립보드 복사 정상("복사됨 ✓"). 단, 복사 후 어디로 보내라는 안내가 약함.

##### 1-4. PC(1280)
- 버튼이 "내용 복사"로 바뀌고 안내문 "PC에서는 문자 앱이 열리지 않습니다… '내용 복사' 후 카카오톡·문자로 보내시거나 전화" → 복사 정상, 미리보기 + "복사한 내용을 보내 주시거나 010-3406-0071 으로 전화 주세요."
- 문제: **PC 사용자에게 실제 '보낼 곳'이 없음**(카톡 채널 없음, 이메일 미공개). 사실상 "전화하세요". 옆 패널 "문자 문의" 버튼이 PC에서도 sms: 링크로 남아 있어 윈도우에서는 눌러도 의미 없음(맥은 메시지 앱이 열림).
- 해결: PC에서는 **QR 코드 "휴대폰으로 이어서 접수"**(QR 스캔 → 같은 sell.html, 선택값을 URL 파라미터로 넘김) + 전화번호 크게.

##### 1-5. 사진
- 현재 사진을 보낼 방법 없음. 가장 단순한 무설정 해법: 문자 앱이 열린 뒤 **＋(사진) 버튼으로 첨부 → MMS**. 아이폰 메시지·삼성 메시지 모두 작성 화면에서 사진 추가 가능(수신자·본문은 미리 채워진 상태).
  페이지에 "📷 문자 앱이 열리면 ＋ 버튼으로 사진 3~5장 같이 보내 주세요" 한 줄이면 됨. (MMS 사진은 통신사에서 압축됨 — 판단용으로는 충분, 원본이 필요하면 카톡 채널 단계에서)

##### 1-6. 사장님이 받는 것
- 매도인 번호에서 온 장문 문자(사진 첨부 시 MMS). 사장님 휴대폰 기본 문자함에 쌓임 → 별도 앱·로그인 불필요. 단점: 목록/검색/엑셀 정리는 안 됨(업그레이드 B에서 해결).

##### 1-7. 기타 관찰
- 헤드리스 Chromium은 isMobile 에뮬레이션에서도 `(pointer: fine)` 이 true로 나옴 — 현재 코드는 UA(Android|iPhone|iPad)도 함께 보므로 휴대폰 경로가 정상 선택됨. 단 iPadOS(UA가 Macintosh)+트랙패드는 PC 경로로 갈 수 있음(영향 작음).
- 사이트 CSS에 이미 `.chip`/`.chips`(aria-pressed 토글 버튼, 44px) 스타일이 있음 → 칩 폼 구현 시 재사용 가능(시안에서 label에 .chip을 쓰니 테두리가 이중으로 겹침 — 구현 시 `<button class="chip" aria-pressed>` 패턴이나 다른 클래스명 사용).

#### 1-8. 시안 검증 (scratch/proto/sell2.html, 저장소 수정 없음)
- 구성: [무엇을] 토지(전·답)/대지/임야/전원주택/농가주택/상가·창고/기타 · [거래] 매매/전세·월세/아직 고민 중 · [어디] 양평 12개 읍·면 칩 + 양평 외 + 리(선택 입력) · [해당되는 것, 복수] 급하게 팔아야 함/상속받은 땅/농지 전수조사 관련/세금 먼저 상담/시세만 궁금 · [면적·희망가] 접힘(선택) · [연락 편한 때] 아무 때나/오전/오후/저녁/문자로만 · [성함·다른 번호] 접힘(선택) · 하단 고정 [문자로 보내기][전화] · 사진 안내 1줄.
- `?v=6noMRA8Ji1E` 로 열면 videos.json 에서 제목을 찾아 "보고 오신 영상: …" 표시 + 문자 끝줄 "본 영상: …".
- 실측: **탭 7번 + 3글자("월산리")** (현재 77자 + select 2번). 문자 108자/186바이트:
  ```
  [매물 내놓기·홈페이지]
  토지(전·답) 매매
  양평 지평면 월산리
  상속받은 땅, 농지 전수조사 관련
  ```

#### 2. 채널 현황 (public/data/videos.json, 68개, 2026-10-15 기준)
- build.py `is_listing_video` 기준: **정보/법령 등 42개(본편 14, 쇼츠 28)**, 매물 26개(본편 16, 쇼츠 10). 최근 한 달은 농지 전수조사·특별조치법·양도세·비사업용 토지 영상이 대부분.

- 홈페이지에는 '본편 + 매물 + 12개월 이내'만 노출 → **정보·법령 영상은 홈페이지에 하나도 안 나옴.** "모든 유튜브를 보고 내놓기"를 하려면 정보 영상도 사이트에 들어와야 함(아래 4-B).
- 중요: 사장님의 정보 영상 설명에는 이미 이해상충 고지가 있음 — 예) "저는 중개업을 하는 공인중개사입니다. 농지를 파는 일이 실제로 이뤄지면 저에게 중개보수가 생길 수 있어, 이 영상은 매도·위탁을 권하지 않고 확인할 일만 정리합니다." / "이 영상은 특정 매물 소개나 매도 권유가 아닙니다."
  → **정보 영상의 CTA는 이 고지와 충돌하지 않게 '상담·접수 창구 안내'로만** 써야 함("지금 파세요" 금지). 4-C 문구 참조.

##### 5-1. sms: 링크

#### 7. 구현 메모 (다음 작업자용, 저장소 반영은 별도 작업)
