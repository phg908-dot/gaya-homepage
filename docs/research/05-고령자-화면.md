# 05. 50대 이상 방문자를 위한 화면 단순화 — 조사·점검·명세

## 요약 (5줄)

1. 방문자 대부분이 50대 이상이다. 배포본을 휴대폰(390px)·PC(1280px)에서 측정한 결과 화면 글자의 69~81%가 16px 미만, 흰 테두리 버튼 대비 약 1.2:1, 홈 첫 화면에 누를 것이 23개였다.
2. 상세 페이지에서 전화 버튼이 세 번째 화면에야 나오고, 매물 접수는 입력칸 8개로 길다.
3. 명세: 본문 18px(16px 미만 금지), 보조 글자 #3f4a59(대비 9:1), 누르는 곳 48px 이상, 주요 버튼 56px, 메뉴는 3개(매물 보기·땅·집 내놓기·사무소 안내), '글자 크게' 버튼.
4. 없앨 것: 빠른 칩·정렬·필터·찜·작은 배지·영상 칩. 항상 보이게: 전화 버튼, '땅·집 내놓기' 띠, '영상에서 본 매물번호' 입력칸. 쉬운 말로 바꾸기(No. → 매물번호 등).
5. 근거는 KWCAG 2.2, WCAG 2.2(누르는 크기), NN/g 고령자 연구, 금융위 고령자 앱 지침(검색 요약 기반, 일부 수치 미검증). **아직 구현 전**이며 명세의 '내용 복사'·QR 관련 부분은 사장님 결정(복사·QR 금지)을 따른다.

> 아래는 2026-10-16 조사 결과 원문입니다. 임시 폴더 경로를 지우고, 다른 사무소·가게의 연락처와 개인 이름, 지번을 가린 것 외에는 그대로 두었습니다.

## 원본 조사 결과 (요약 보고)

### 50대 이상 방문자용 단순화: 조사·점검·명세

배포용으로 빌드한 사이트를 휴대폰 화면(390×844)과 PC 화면(1280×800)에서 측정하고 스크린샷으로 확인했습니다. 원본 폴더 /home/user/gaya-homepage 는 수정하지 않았습니다. 전체 메모는 이 문서 아래 '상세 노트'에 있습니다.

#### 1) 조사 결과
조사는 검색 결과로만 했습니다. 프록시가 원문 페이지를 막아서 열지 못한 곳이 있습니다(nngroup.com, w3.org, ncbi, fsc.go.kr, a11ykr.github.io).

- **한국형 웹 콘텐츠 접근성 지침 2.2 (KS X OT0003:2022)**: 2022년 12월 28일 고시. 4원칙·14지침·33개 검사항목.
  - 명도 대비 4.5:1, 컨트롤 대각선 6.0mm 이상이라는 항목별 수치는 기억에 의존한 것이고 원문으로 확인하지 못했습니다.
  - 출처: websoul.co.kr/accessibility/WA_guide22.asp, codeslog.com/posts/kwcag-22-guide/
- **WCAG 2.2 누르는 대상 크기**: 최소 기준(AA)은 24×24px, 강화 기준(AAA)은 44×44px. 도움·연락 수단은 모든 페이지에서 같은 자리에 둬야 합니다(3.2.6). 애플은 44pt, 구글 머티리얼은 48dp를 권합니다.
  - 출처: disabilityworld.org/.../2-5-8-target-size-minimum/, github.com/w3c/wcag/issues/1831
- **NN/g 고령자 사용성 연구**:
  - 65세 이상은 젊은 층보다 43% 느리고, 과제를 포기하는 비율이 거의 2배입니다.
  - 처음 실패하면 다른 방법을 잘 시도하지 않습니다.
  - 작은 대상과 촘촘한 링크, 드롭다운이 어렵습니다.
  - 기본 글자를 크게 하고, 페이지 안에 글자 키우기 버튼을 두라고 권합니다.
  - 출처: nngroup.com/articles/usability-for-senior-citizens/, /usability-seniors-improvements/
- **NIA/NLM 고령자 웹 체크리스트**: 본문 12~14pt(약 16~19px). 출처: corpora.tika.apache.org/.../562513.html
- **서울디지털재단 고령층 디지털 접근성 표준**: 앱·모바일 웹 글자 14포인트 이상, 쉬운 용어. 출처: boannews.com idx=96003
- **금융위 고령자 친화 금융앱 지침 (2022년 시행)**: 쉬운 용어와 짧은 문장, 한 화면에 알맞은 정보량, 자주 쓰는 기능 위주, 고령자 모드로 들어가는 길 최소화, 다시 배워야 할 만큼 큰 개편 피하기, 누구나 고를 수 있는 모드. 출처: fsc.go.kr/no010101/77426, khan.co.kr/article/202202241436011
- **은행 '쉬운 모드'가 바꾼 것**: 큰 글씨, 메뉴 최소화, 아이콘을 글자로 바꿈('이체' → '송금'). 출처: ajunews.com/view/20230320095037402, bravo.etoday.co.kr/view/atc_view/18982
- **키오스크 고령자 연구**: 고령자는 테두리가 없는 버튼을 버튼으로 알아보지 못합니다. 출처: koreascience JAKO201914456457359
- **노안**: 보통 40~45세에 시작되어 50대에는 대부분 겪습니다. 출처: eyewiki.org/Presbyopia
- **확인하지 못한 것**: 네이버 '큰 글씨 모드'와 카카오톡 '쉬운 모드'는 출시 자료를 찾지 못했습니다. 확인된 카카오 사례는 '더 쉬운 카톡설명서'와 고대비 테마뿐입니다(kakaocorp.com/page/detail/11024, /7880).

#### 2) 점검 결과: 60세 이용자가 휴대폰에서 겪을 문제
1. **영상만 보고는 어떤 매물인지 알 수 없습니다.** 영상 카드에는 해시태그가 섞여 2줄에서 잘리는 제목과 14px 날짜뿐이고, 가격·위치·면적·매물번호가 없습니다.
2. **글자가 너무 작습니다.** 화면 글자의 69~81%가 16px 미만입니다.
   - 12px: 매물 카드 위 작은 표시(급매·추천·매매 등)
   - 13px: 안내문, 확인 안내, 매물번호 표시
   - 14px: 소재지, 날짜, 사무소 정보, 상세 페이지와 접수 페이지의 버튼
   - 15px: 메뉴, 영상 제목, 매물 정보 표
3. **회색 글자가 흐립니다.** 기준(4.5:1)은 넘지만 작은 회색 글자(#5b6676)는 대비가 5.4~5.8:1이라, 고령자에게 권하는 7:1에 못 미칩니다.
4. **흰 테두리 버튼이 거의 보이지 않습니다.** 테두리 대비가 1.16~1.26:1로, 버튼 테두리 기준인 3:1(WCAG 1.4.11)에 크게 못 미칩니다. 해당 버튼은 찜하기, 공유하기, 인쇄·PDF, 내용 복사, 네이버 지도에서 보기, 조건 초기화, 닫기입니다.
5. **홈 첫 화면에 누를 것이 23개입니다.** 메뉴 4, 검색, 빠른 칩 4, 정렬, 필터, 가로로 넘겨야 하는 종류 칩 6, 찜, 하단 버튼 2.
   - 첫 매물 카드는 작은 표시만 겨우 보입니다.
   - 매물 4건뿐인데 홈이 6.8화면 길이입니다.
   - PC에서는 첫 화면 800px 중 660px를 상단 큰 영역이 차지해 매물이 하나도 보이지 않습니다.
6. **같은 기능이 겹치고 필요 없는 기능이 많습니다.**
   - 상단 빠른 칩과 아래 종류 칩이 겹칩니다.
   - 필터 시트에 시·도, 시·군 선택이 있지만 매물이 모두 양평군이라 선택지가 하나뿐입니다.
   - 정렬 드롭다운이 있고, 찜은 이 기기에만 저장됩니다.
7. **상세 페이지에서 전화가 늦게 나옵니다.**
   - 문의 상자는 매물 정보 표 21줄 아래, 세 번째 화면에야 나옵니다.
   - 그 상자의 큰 버튼은 '문자 문의'(14px)이고, 전화는 글자 링크입니다.
8. **매물 접수 페이지가 깁니다.** 입력칸이 8개이고, '전화로 바로 상담' 상자는 네 번째 화면에 있으며 그 안의 버튼도 '문자 문의'입니다.
9. **작게 누르는 곳이 있습니다.** 경로 표시 '홈' 14×39px, '→' 글자 링크들 높이 20~26px, 푸터 메뉴 28×43px.
10. **200% 확대에서 깨집니다.** 메뉴가 한 글자씩 줄바꿈되고('매/물', '사무/소/소개'), 카드 최소 폭(260px, 240px) 때문에 가로 스크롤이 생깁니다. 크기가 모두 px로 되어 있어 '글자 크게' 버튼을 만들려면 rem으로 바꿔야 합니다.
11. **어려운 말과 영어가 있습니다.** No., PDF, 필터, 상세 조건, 초기화, 추천·최신순, 찜, 매물 정보 연결됨, 공부서류, 갱신일, 현 이용상태, 지목 '답/대'.

**이미 잘 되어 있는 것(유지)**: 모바일 하단 고정 전화·문자 바(54px), 주요 버튼 44px 이상, 지번 비공개, 계약완료 매물 제외, 모든 페이지 푸터의 사무소 법정 표시 정보.

#### 3) 단순화 명세

**디자인 토큰** (크기는 rem 단위로 전환)
- 글자 크기
  - 본문 18px, 글자 굵기 500, 줄간격 1.7
  - 어디서도 16px 미만 금지
  - 카드 제목 20, 소제목 24, 큰 제목 28(PC 34)
  - 가격: 카드 26, 상세 32
- 색상
  - 본문 #111 (18.9:1)
  - 보조 글자 #3f4a59 (흰 바탕 9.0:1, 회색 바탕 8.3:1)
  - 전화 버튼 #0a5c32 바탕에 흰 글자 (8.1:1)
  - 매물 내놓기 버튼: 금색 #c9a46a 바탕에 #13253d 글자 (6.6:1)
  - 급매 표시 #a81f25 (7.3:1)
  - 입력칸·테두리 버튼 테두리 2px #5b6676 (5.8:1), 카드 테두리 #8a96a6 (3.0:1)
  - 푸터 글자 #dfe5ee (14.1:1)
- 크기와 간격
  - 누를 수 있는 곳은 최소 48×48px, 서로 8px 이상 띄움
  - 주요 버튼 56px, 하단 고정 바 60px·20px
  - 입력칸 56px, 18px

**없앨 것**
- 홈 상단의 작은 문구, 숫자 현황(거래 가능 매물·매물 영상·읍면 수)
- 빠른 칩, 정렬, 필터 전체, 찜
- 추천·급매 가로 넘김 줄, 카드 위 작은 표시, 카드 요약 줄
- 영상 페이지의 칩·검색
- 상세 페이지의 경로 표시, 찜, 인쇄(PC에만 남김), 태그
- 모바일의 '내용 복사'
- '영상' 메뉴는 '매물 보기'에 합침

**크게, 항상 보이게 할 것**
- 하단 바: [☎ 전화 걸기](초록) + [✉ 문자 보내기]
- PC 헤더 오른쪽에 전화번호 버튼
- 상세 페이지: 가격 바로 아래 '한눈에 보기' 6칸, 그 아래 큰 [전화 걸기] 버튼과 "매물번호 ○○번이라고 말씀해 주세요" 안내
- 모든 페이지 푸터 위에 금색 '땅·집 내놓기' 띠
- 홈 상단에 '영상에서 본 매물번호' 입력칸 하나 (숫자 자판). 영상 설명의 '◑ 매물번호 : 350'과 바로 이어집니다.
- 카드마다 [자세히 보기 ›] 버튼

**메뉴**
- 최대 3개: [매물 보기] [땅·집 내놓기] [사무소 안내]
- 접지 않고 항상 보이게 하며, 글자가 줄바꿈되지 않게 함
- 페이지 깊이는 2단계(목록 → 상세), 상세 페이지 위아래에 [← 매물 목록으로]

**쉬운 말** (바꿀 말 전체 목록은 메모 3.5절)
- 매물 접수 → 땅·집 내놓기
- No. → 매물번호
- 공유하기 → 가족에게 보내기
- 지목 답 → 답(논)
- 정보 갱신일 → 정보 확인한 날
- 날짜는 '2026년 10월 12일'
- 오류 문구에 예시 번호를 넣고, 입력한 값은 지우지 않음

**'글자 크게' 버튼**
- 헤더에 한 번 누르는 버튼 하나. 누르면 글자가 120%로 커지고 설정은 그 브라우저에 저장됩니다.
- 그러려면 크기를 rem으로 바꾸고 카드 폭 계산식을 고쳐야 하며, 200% 확대에서 가로 스크롤이 없어야 합니다.

**페이지별 배치**
- 홈: 짧은 상단 영역 → 종류 버튼 2열 → 매물 카드 한 줄씩 → 내놓기 띠 → 오시는 길
- 상세: 목록으로 버튼 → 제목·가격 → 영상 → 한눈에 보기 → 전화·문자 → 설명 → 매물 정보 전체 표(펼친 상태) → 사무소 정보 → 비슷한 매물 3개
- 땅·집 내놓기: 맨 위에 [☎ 전화로 내놓기] → 그 아래 문자 양식(필수 2칸 + 종류 선택 + '더 적기')
- 사무소 안내: 전화·오시는 길을 먼저

**지킬 조건**
- 사무소 법정 표시 정보(상호·대표·등록번호·소재지·연락처)는 모든 페이지에 16px 이상으로 표시
- 상세 페이지의 매물 정보 표는 접지 않음
- 지번 비공개, 계약완료 매물 제외, 방향은 '(건물 정면 기준)', 쇼츠 제외, 확인 안 된 사무소 정보는 숨김

**구현 후 확인할 것**: 16px 미만 글자 0개, 글자 대비 7:1 이상, 누르는 곳 48px 이상, 홈 첫 화면의 버튼·입력칸 10개 이하(제안안은 9개), 200% 확대에서 가로 스크롤 없음, 실제 50~60대 손님에게 "매물번호 350을 찾아 전화하기"를 30초 안에 할 수 있는지 시험.

##### 60세 이용자가 휴대폰에서 겪을 문제
1. **영상만 보고는 어떤 매물인지 알 수 없다** (사장님 지적). 영상 카드에는 유튜브 제목(해시태그가 섞여 2줄에서 '#…'로 잘림)과 날짜(14px)뿐이다. 가격, 위치, 면적, 매물번호가 없고, 대부분 상세 페이지 링크도 없다.
2. 홈 첫 화면에 누를 것이 23개 있다: 메뉴 4, 검색, 빠른 칩 4, 정렬 select, 필터, 종류 칩 6(가로로 넘겨야 함), 찜 하트, 하단 2. 매물 카드는 배지만 겨우 보인다. 'n 거래 가능 매물 / n 매물 영상 / n 읍·면 지역' 같은 숫자와 상단 작은 문구(eyebrow)는 쓸모없는 정보다.
3. 같은 기능이 두 번 나온다: 히어로의 빠른 칩과 아래 종류 칩. 정렬(드롭다운)과 필터 시트(시·도/시·군/읍·면 select 3개, 거래 유형, 가격, 면적, 영상만, 초기화)는 매물이 거의 다 양평군이라 시·도·시군 선택지가 하나뿐이다. 드롭다운과 하단 시트는 NN/g가 말한 고령자에게 어려운 형태 그대로다.
4. '찜'(♡, 이 브라우저에만 저장)은 고령자가 이해하기 어렵고, 기기를 바꾸면 사라진다.
5. 본문 정보 대부분이 12~15px이고 흐린 회색(5.4~5.8:1)이다. 노안이 있으면 소재지, 요약, 날짜, 안내문, 사무소 정보를 읽기 어렵다.
6. 외곽선 버튼의 테두리가 거의 보이지 않는다 (1.2:1).
7. 상세 페이지:
   - 문의 상자가 명시사항 표(21줄) 아래 세 번째 화면에야 나온다.
   - 그 상자에서 가장 눈에 띄는 버튼이 '문자 문의'(14px)이고 전화는 글자 링크다.
   - 찜하기·공유하기·인쇄·PDF 버튼이 가격 바로 아래 있어 헷갈린다.
   - 경로 표시가 작다 (14px).
   - 표의 용어: 지목 '답/대', 용도지역, 현 이용상태, 사용승인일, 전용면적, 정보 갱신일, 공부서류.
8. 접수 페이지:
   - 입력칸이 8개다 (성함, 연락처*, 소재지*, 종류, 거래, 면적, 가격, 추가 내용).
   - 버튼 2개(문자로 보내기, 내용 복사)가 14px다.
   - '전화로 바로 상담' 상자는 양식 아래 네 번째 화면에 있고, 그 안의 유일한 버튼도 '문자 문의'다.
   - 안내문 13px: '문자 앱이 열립니다…'.
9. 메뉴 이름이 모호하다. '매물 접수'는 파는 사람용인지 알기 어렵다. '영상'과 '매물'은 사실상 같은 목록이다.
10. 영어·약어·전문용어: No., PDF, 필터, 상세 조건, 조건 초기화, 추천·최신순, 찜, 매물 정보 연결됨, 공부서류, 갱신일, 세컨하우스, ☎ ✉ ♡ ▶ → 같은 기호.
11. 200% 확대나 휴대폰 글자 크게 설정에서 메뉴가 글자 단위로 깨지고 가로 스크롤이 생긴다.
12. PC: 히어로 때문에 첫 화면에 매물이 없다. 사이드바 필터 7개, 정렬, 카드 3열에 13~14px 글자. 그래도 상단의 전화번호 버튼(15px)은 좋다.

- 모바일 하단 고정 바: 높이 54px, 18px 굵은 글자, 전화·문자

- **전화**:
  - 모바일 하단 고정 바: [☎ 전화 걸기](초록) + [✉ 문자 보내기](navy), 높이 60px, 20px

  - 전화 버튼은 모든 페이지에서 같은 자리에 둔다 (WCAG 3.2.6 일관된 도움)

- 매물 카드 안에 [자세히 보기 ›] 버튼을 넣는다 (카드 전체를 누를 수 있다는 것을 고령자는 잘 모름)

##### 3.4 내비게이션
- 상단 메뉴는 **최대 3개**: [매물 보기] [땅·집 내놓기] [사무소 안내]. 접지 않고 항상 보이게 하고(햄버거 금지), `white-space: nowrap`을 준다. 3칸이 같은 폭이고, 글자가 커지면 2줄로 넘어간다.
- 깊이는 최대 2단계 (홈 목록 → 상세). 상세 페이지 위와 아래에 [← 매물 목록으로] 버튼(48px)을 둔다. 브라우저 뒤로 가기를 하면 보던 위치를 되살린다 (현재 기능 유지).
- 헤더 오른쪽에 [가 글자 크게] 버튼.

##### 3.5 쉬운 말 (기존 → 바꿀 말)
- 메뉴·버튼:
  - 매물 → 매물 보기
  - 매물 접수 → 땅·집 내놓기
  - 사무소 소개 → 사무소 안내
  - 영상 → (매물 보기에 합침)
  - 전화 → 전화 걸기
  - 문자 / 문자 문의 → 문자 보내기
  - 공유하기 → 가족에게 보내기(카톡·문자)
  - 인쇄 · PDF → 인쇄하기 (PC만)
  - 매물 영상 모두 보기 → → [영상 매물 모두 보기] 버튼
  - No.1001 → 매물번호 1001
  - 필터 / 상세 조건 / 조건 초기화 / 추천·최신순 / 찜 / 매물 정보 연결됨 → 없앰
- 매물 정보 용어 (명시사항 이름은 법적 용어이므로 유지하고 괄호로 풀이):
  - 지목 '답' → 답(논), '전' → 전(밭), '대' → 대(대지), '임' → 임야(산)
  - 전용면적 → 실내 면적(전용)
  - 현 이용상태 → 지금 쓰는 용도
  - 정보 갱신일 → 정보 확인한 날
  - 공부서류 → 등기부등본·토지대장 같은 서류
- 날짜: '2026. 10. 12.' → '2026년 10월 12일'
- 월세 가격은 두 줄로: '보증금 3,000만원' / '월세 150만원'
- 오류 문구: "전화번호를 다시 확인해 주세요 (예: 010-1234-5678)". 칸 아래 빨간 글자(#a81f25) 17px와 ! 표시. 이미 입력한 값은 지우지 않는다 (반복 입력 정보).
- PC 안내문 "PC에서는 문자 앱이 열리지 않습니다…" → "컴퓨터에서는 문자가 보내지지 않습니다. 전화 010-3406-0071로 말씀해 주세요."
- 문장은 짧게, 존댓말 '~하세요/~드립니다', 한 문장에 한 가지 정보. 영어와 약어는 쓰지 않는다.

##### 3.6 '글자 크게' 버튼 (선택 기능이지만 권장: NN/g 권고 + 은행 '쉬운 모드'와 같은 방식)
- 헤더 오른쪽 [가 글자 크게] ↔ [가 글자 보통] 버튼. `aria-pressed`를 쓰고 높이 48px.
- `<html data-text="lg">`이면 html font-size가 120% (본문 18 → 21.6px). 모든 크기가 rem이어야 한다.
- 설정은 localStorage에 저장한다 (try/catch로 감싸고, 저장이 안 되어도 기본 크기로 정상 표시). 슬라이더 말고 한 번 누르는 버튼 하나.
- 확인 사항: 이 상태와 200% 확대에서 가로 스크롤 0, 메뉴가 글자 단위로 깨지지 않음.
  - `.cards`와 `.vgrid`는 `minmax(min(300px,100%),1fr)`로 고친다
  - `.nav a{white-space:nowrap}`
- 브라우저 확대와 휴대폰 글자 설정도 그대로 따른다.

##### 3.8 반드시 지킬 것 (법·사장님 조건)
- 모든 페이지 푸터에 상호, 대표, 등록번호, 소재지, 연락처를 16px 이상, 대비 7:1 이상으로 항상 보이게 한다.
- 상세 페이지의 명시사항 표는 접지 않는다.
- 지번은 절대 보이지 않는다. 계약완료 매물과 그 영상은 계속 제외한다.
- 방향은 '(건물 정면 기준)'.
- 쇼츠는 싣지 않는다.
- 확인되지 않은 사무소 정보(상담 시간, 카카오 채널, 휴대폰 번호)는 값이 없으면 칸을 숨긴다.
- 면적은 ㎡를 먼저 쓰고 평은 괄호에 쓴다 (계량법).

##### 3.9 검증 (구현 후 Playwright로 확인)
- 모바일의 모든 페이지에서 계산된 font-size가 16px 미만인 텍스트 0개
- 텍스트 대비는 7:1 이상. 금색 버튼, 28px 이상의 큰 글자는 4.5:1 이상
- 누를 수 있는 요소는 모두 48×48 이상 (문단 안 링크 제외)
- index 모바일 첫 화면 컨트롤 10개 이하. 제안안은 9개: 이름, 글자 크게, 메뉴 3, 입력칸, 찾기, 하단 바 2
- 195px 폭(200% 확대)과 '글자 크게' 켠 상태에서 가로 스크롤 0
- 실제 50~60대 손님 2~3명에게 "영상에서 본 매물번호 350을 찾아 전화해 보세요"를 시켜 30초 이내, 잘못 누름 0회
